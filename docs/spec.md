# 릴리스 개발용 스펙 문서
목적: PRD / MVP / GDD를 개발 실행용 스펙으로 변환한다.
원칙: 문서에 없으면 이번 MVP에 없는 것으로 간주한다. 모호한 규칙은 구현 판정 기준까지 명시한다.
---
## 1. 소스 오브 트루스
- PRD: 왜 만드는가 / 프로젝트 목표 / 제품 방향
- MVP: 이번 릴리스 범위와 제외 범위
- GDD: 전투, 맵, 보상, 장비, 유물, 이벤트 규칙
- 이 문서: 개발자가 바로 구현할 수 있는 판정 기준과 우선순위
---
## 2. MVP 범위 고정
- 대상: 1막 플레이어블
- 파티: 시작 파티 3인 고정
- 전투: 속도 기반 턴제, 실시간 입력/QTE 없음
- 콘텐츠 노드: 일반 전투 / 이벤트 / 보물 / 상점 / 모닥불 / 유니크 몬스터 / 보스
- 해금: 신규 콘텐츠 해금 중심, 영구 스탯 강화는 최소화
---
## 3. 기능별 완료 기준
- 전투 완료: 턴 순서가 정상 동작하고, HP/MP/상태이상/승패 판정이 끝까지 처리된다.
- 맵 완료: 노드 선택 → 노드 진입 → 결과 반영 → 다음 노드 이동이 끊김 없이 이어진다.
- 보상 완료: 전투/이벤트/보물/상점/모닥불 결과가 런 상태에 반영된다.
- 해금 완료: 조건 충족 시 신규 콘텐츠가 다음 런에서 확인 가능하다.
---
## 4. 구현 우선순위
- [ ] 전투 코어: 3인 파티 vs 적 2~4명, 기본 공격/스킬/승패
- [ ] 상태이상: 출혈/화상/파쇄/둔화/약화/기절
- [ ] 보상 루프: 골드/장비/유물/물약 지급
- [ ] 맵 노드: 분기 이동 및 노드 타입 처리
- [ ] 상점/모닥불: 구매, 회복, 강화, 투자
- [ ] 1막 보스: 빌드 검증용 패턴 1종
---
## 5. 데이터 계약
- CharacterTable: 캐릭터 기본 스탯, 역할군, 스킬 참조
- SkillTable: 비용, 대상, 계수, 상태이상 효과
- EnemyTable: 패턴, 스탯, 드랍
- RelicTable: 조건, 시너지, 페널티
- EquipmentTable: 슬롯, 등급, 옵션, 강화
- NodeTable: 노드 타입, 출현 조건, 보상
- EventTable: 선택지, 결과, 해금 조건
- RewardTable: 보상 묶음과 확률
---
## 6. 판정이 필요한 모호한 항목
- 피해 계산식 v0.1
- 속도 동률 처리 우선순위
- 상태이상 중첩/갱신/면역 규칙
- 장비 강화 단계별 효과
- 이벤트 선택지 분기 및 실패 결과
- 보상 드랍 테이블의 최저 보장 규칙
---
## 7. 검증 루프
- 포맷터 / 린트 / 타입체크
- GUT 테스트로 전투, 상태이상, 노드 이동 검증
- 수동 플레이 시나리오로 1막 완주 확인
- 실패 로그를 기준으로 규칙 문서 갱신
---
## 8. 이번 문서의 사용법
- 각 기능은 이 문서의 완료 기준을 만족할 때만 Done 처리한다.
- 구현 전에 관련 Linear 이슈를 먼저 만든다.
- 스펙에 없는 동작은 추가하지 않는다.

## 9. 판정 기본안 (MVP)
아래 규칙은 밸런스 검토용 초안이다. 최종 적용은 13~15장의 최종 스펙을 우선한다.
### 9-1. 피해 계산
- 기본 공식: 최종 피해 = max(1, floor(공격력 × 스킬 계수) - 방어력)
- 방어력 관통, 속성 상성, 치명타 피해 증가 스탯은 MVP에서 제외한다.
- 연속 피해/고정 피해는 스킬 설명이 따로 없으면 같은 공식으로 계산한다.
### 9-2. 속도 동률 우선순위
- 매 턴 시작 시 현재 속도를 기준으로 행동 순서를 다시 계산한다.
- 속도가 같으면 아군이 적보다 먼저 행동한다.
- 같은 진영 내에서는 현재 HP 비율이 낮은 유닛이 먼저 행동한다.
- 그마저 같으면 내부 ID 순서로 고정한다.
### 9-3. 상태이상 규칙
- 출혈 / 화상: 최대 3중첩, 재적용 시 중첩 +1 및 지속시간 갱신.
- 둔화 / 약화 / 파쇄: 중첩하지 않고 지속시간만 갱신한다.
- 기절: 중첩하지 않고 행동 불가 1턴으로 처리한다.
- 상태이상 적중은 스킬 기재 확률을 우선하고, 효과 적중과 저항은 보정값으로만 사용한다.
- 보스 전용 면역은 별도 태그로 처리하며, 일반 몬스터는 기본적으로 면역 태그를 사용하지 않는다.
### 9-4. 장비 강화 규칙
- +1: 주옵션 10% 상승
- +2: 주옵션 추가 10% 상승, 부옵션 1개 강화
- +3: 장비 고유 효과를 개방하거나 기존 고유 효과를 강화
- 강화 비용은 장비 등급별 비용 테이블에서 관리한다.
### 9-5. 이벤트 분기 / 실패 규칙
- 모든 이벤트는 최소 2개 선택지를 가진다.
- 실패 선택지는 HP / MP / 골드 감소, 상태이상 부여, 전투 발생 중 하나로 귀결된다.
- 숨겨진 선택지는 사전 조건 충족 시에만 노출된다.
- 이벤트는 결과 처리 후 반드시 다음 노드로 이어지며, 진행이 막히는 형태는 허용하지 않는다.
### 9-6. 보상 최저 보장 규칙
- 일반 전투: 골드 + 보상 1회는 반드시 지급한다.
- 엘리트 / 유니크 전투: 골드 + 고급 이상 보상 후보를 지급한다.
- 보물 노드: 유물 1개를 확정 지급한다.
- 보스 노드: 유물 1개와 해금 체크를 반드시 지급한다.
- 보상 결과가 비어 있는 경우는 예외로 간주하고 버그로 처리한다.

## 10. 밸런스 초안 v0.1
아래 수치는 MVP 구현용 초기값이다. 구현은 이 수치를 기준으로 고정하고, 이후 플레이테스트에서만 조정한다.
### 10-1. 플레이어 시작 스탯
- 전위 딜러: HP 120 / MP 30 / 공격력 18 / 방어력 6 / 속도 14 / 치명타율 10% / 효과 적중 5% / 효과 저항 0%
- 수호자: HP 150 / MP 24 / 공격력 14 / 방어력 10 / 속도 10 / 치명타율 5% / 효과 적중 5% / 효과 저항 5%
- 마법 지원가: HP 100 / MP 36 / 공격력 16 / 방어력 5 / 속도 12 / 치명타율 8% / 효과 적중 10% / 효과 저항 5%
- 모든 캐릭터의 기본 MP 최대치는 역할별 수치를 따르며, 전투 시작 시 MP는 최대치의 50%로 시작한다.
### 10-2. 적 스탯 밴드 (1막)
- 일반 적: HP 70~95 / 공격력 12~15 / 방어력 4~6 / 속도 9~12
- 엘리트 적: HP 130~170 / 공격력 16~20 / 방어력 6~8 / 속도 10~13
- 보스: HP 450 / 공격력 22 / 방어력 8 / 속도 10
- 유니크 몬스터: HP 180 / 공격력 18 / 방어력 7 / 속도 14
### 10-3. 스킬 계수
- 기본 공격 계수: 1.00
- 소형 단일 대상 스킬: 1.30
- 중형 단일 대상 스킬: 1.60
- 광역 스킬: 0.70
- 보호/버프 스킬은 피해 계수 없이 자원과 상태만 변경한다.
### 10-4. 상태이상 수치
- 출혈: 1스택당 턴 종료 시 최대 HP의 5% 피해, 최대 3중첩, 지속 3턴
- 화상: 1스택당 턴 종료 시 최대 HP의 6% 피해, 최대 3중첩, 지속 3턴
- 둔화: 속도 -20%, 지속 2턴
- 약화: 공격력 -20%, 지속 2턴
- 파쇄: 방어력 -25%, 지속 2턴
- 기절: 행동 불가 1턴
- 상태이상은 중첩 허용 항목과 갱신 항목을 구분하며, 동일 타입 재적용 시 지속시간은 항상 갱신한다.
### 10-5. 경제 / 상점 / 강화
- 런 시작 골드: 50
- 일반 전투 보상 골드: 20~35
- 엘리트 전투 보상 골드: 60~80
- 보스 보상 골드: 120
- 상점 일반 장비 가격: 30~45
- 상점 유물 가격: 60~90
- 상점 물약 가격: 15~25
- 모닥불 휴식: 최대 HP의 35% 회복
- 모닥불 능력치 투자: 한 번에 1개 스탯 +1, 비용 25골드
- 장비 강화 +1 비용: 일반 20 / 고급 35 / 희귀 50
- 장비 강화 +2 비용: 일반 35 / 고급 55 / 희귀 80
- 장비 강화 +3 비용: 일반 60 / 고급 90 / 희귀 120
### 10-6. 보상 수량 / 보장
- 일반 전투: 골드 20~35 + 공용 보상 1회(13장 규칙 기준)
- 엘리트 전투: 골드 60~80 + 상위 보상 1회(13장 규칙 기준)
- 보물 노드: 유물 1개 확정
- 보스 노드: 유물 1개 확정 + 해금 체크 1회
- 이벤트 노드: 보상은 선택지 1개당 1회만 발생하며, 중복 보상은 허용하지 않는다.
### 10-7. 1막 보스 기준선
- 1막 보스의 평균 전투 시간 목표: 6~8턴
- 1막 일반 전투의 평균 전투 시간 목표: 2~4턴
- 1막 엘리트 전투의 평균 전투 시간 목표: 4~6턴
- 파티는 1막 보스전에서 최소 1회 이상 회복 또는 방어 선택을 강제받도록 설계한다.

## 11. 모호한 항목 결정 초안 v0.1
아래 항목은 MVP 구현을 위해 우선 확정하는 초안이다. 구현은 이 기준으로 시작하고, 플레이테스트로만 수정한다.
### 11-1. 치명타
- MVP에서도 치명타를 사용한다.
- 치명타 배수는 1.5배 고정으로 둔다.
- 치명타 확률은 캐릭터/장비/유물/스킬에서 더해지는 최종 수치로 계산한다.
### 11-2. 효과 적중 / 효과 저항
- 최종 상태이상 성공 확률 = clamp(기본 확률 + 효과 적중 - 대상 효과 저항, 0%, 100%)
- 보스 전용 면역은 효과 저항 100% 또는 개별 면역 태그로 처리한다.
- 면역/저항 정보는 EnemyTable에 명시한다.
### 11-3. 연속 피해 / 고정 피해
- 출혈 / 화상 같은 지속 피해는 스킬 설명에 명시된 수치만 적용하고 방어력을 무시한다.
- 고정 피해는 방어력과 치명타의 영향을 받지 않는다.
- 명시가 없는 스킬 피해는 9-1의 일반 피해 공식을 따른다.
### 11-4. 상태이상 중첩
- 출혈 / 화상은 최대 3중첩이다.
- 재적용 시 중첩 1 증가와 지속시간 갱신을 함께 적용한다.
- 이미 최대 중첩이면 중첩은 늘지 않고 지속시간만 갱신한다.
- 둔화 / 약화 / 파쇄 / 기절은 중첩하지 않고 지속시간만 갱신한다.
### 11-5. 이벤트 규칙
- 모든 이벤트는 최소 2개 선택지를 가진다.
- 실패 선택지는 HP / MP / 골드 감소, 상태이상 부여, 전투 발생 중 하나로 귀결된다.
- 전투가 발생하면 일반 전투와 동일한 전투 규칙을 사용하되, 이벤트 전용 적 풀을 사용할 수 있다.
- 이벤트 처리가 끝나면 반드시 다음 노드로 이동한다.
### 11-6. 보상 규칙
- 일반 전투는 골드와 함께 공용 보상 1회를 반드시 지급한다.
- 공용 보상은 장비 또는 물약 중 하나를 의미한다.
- 엘리트 / 유니크 전투는 골드와 함께 상위 보상 1회를 반드시 지급한다.
- 상위 보상은 고급 이상 장비 또는 유물 후보를 의미한다.
- 보물 노드는 유물 1개를 확정 지급한다.
- 보스 노드는 유물 1개와 해금 체크 1회를 확정 지급한다.
- 보상 결과가 비어 있으면 버그로 간주한다.
### 11-7. 장비 강화
- 장비 강화는 +3까지 허용한다.
- +1은 주옵션 상승, +2는 주옵션 추가 상승과 부옵션 1개 강화, +3은 고유 효과 개방 또는 강화다.
- 강화 비용은 장비 등급별 비용 테이블을 따른다.
### 11-8. 1막 콘텐츠 결정 초안
- 1막은 튜토리얼 성격의 붉은 달 아래 폐허 테마로 유지한다.
- 1막은 일반 전투 / 이벤트 / 보물 / 상점 / 모닥불 / 유니크 몬스터 / 보스를 모두 포함한다.
- 1막 보스는 1종만 구현한다.
- 1막 이벤트는 최소 4종을 목표로 한다.
- 1막 일반 적 / 엘리트 적 / 유니크 적은 별도 풀로 관리한다.

## 12. C. 구현 완료 체크리스트
아래 항목이 모두 끝나야 MVP 스펙상 구현 완료로 본다.
- [ ] 전투 코어: 속도 기반 턴 순서, 기본 공격, 스킬, 승패 판정
- [ ] 치명타: 1.5배 고정 배수로 동작
- [ ] 상태이상: 출혈, 화상, 둔화, 약화, 파쇄, 기절
- [ ] 효과 적중 / 저항: 성공 확률 공식 적용
- [ ] 보상 루프: 일반/엘리트/보물/보스 보상 지급
- [ ] 맵 노드: 분기 이동과 노드 타입 처리
- [ ] 상점 / 모닥불: 구매, 회복, 강화, 투자
- [ ] 1막 콘텐츠: 이벤트 4종, 보스 1종, 적 풀 분리
- [ ] 데이터 계약: Character / Skill / Enemy / Relic / Equipment / Node / Event / Reward Table
- [ ] 검증: GUT 테스트 + 수동 1막 완주
## 13. 1막 구현용 최종 스펙 체크리스트
이 섹션이 MVP 구현의 최종 판정 기준이다. 9~11장은 참고용이며, 13~15장은 최종 적용 기준이다.
## 13-1. 스코프 고정
- [ ] 1막만 구현한다.
- [ ] 시작 파티는 3인 고정이다.
- [ ] 실시간 입력 / QTE는 넣지 않는다.
- [ ] 신규 콘텐츠 해금은 넣되, 영구 스탯 강화는 최소화한다.
## 13-2. 전투 규칙
- [ ] 전투는 속도 기반 턴제로 처리한다.
- [ ] 매 턴 시작 시 행동 순서를 다시 계산한다.
- [ ] 속도 동률이면 아군이 적보다 먼저 행동한다.
- [ ] 같은 진영 내 동률이면 현재 HP 비율이 낮은 유닛이 먼저 행동한다.
- [ ] 그마저 같으면 내부 ID 순서를 따른다.
- [ ] 기본 피해는 방어력 차감 후 최소 1 이상으로 처리한다.
- [ ] 치명타는 MVP에서 사용하며, 최종 피해에 1.5배를 곱한다.
- [ ] 방어력 관통, 속성 상성, 치명타 피해 증가 스탯은 MVP에서 제외한다.
- [ ] 지속 피해와 고정 피해는 방어력과 치명타 영향을 받지 않는다.
## 13-3. 상태이상 규칙
- [ ] 출혈과 화상은 최대 3중첩이다.
- [ ] 출혈과 화상은 재적용 시 중첩 +1과 지속시간 갱신을 동시에 적용한다.
- [ ] 둔화, 약화, 파쇄, 기절은 중첩하지 않고 지속시간만 갱신한다.
- [ ] 출혈은 턴 종료 시 최대 HP의 5%를 1스택당 입힌다.
- [ ] 화상은 턴 종료 시 최대 HP의 6%를 1스택당 입힌다.
- [ ] 둔화는 속도 -20% / 2턴이다.
- [ ] 약화는 공격력 -20% / 2턴이다.
- [ ] 파쇄는 방어력 -25% / 2턴이다.
- [ ] 기절은 1턴 행동 불가다.
- [ ] 상태이상 성공 확률은 기본 확률 + 효과 적중 - 대상 효과 저항을 0%~100%로 보정한다.
- [ ] 보스 면역은 EnemyTable의 면역 태그 또는 100% 저항으로 처리한다.
## 13-4. 보상 규칙
- [ ] 일반 전투는 골드 + 공용 보상 1회를 반드시 지급한다.
- [ ] 공용 보상은 장비 또는 물약 중 하나다.
- [ ] 엘리트 / 유니크 전투는 골드 + 상위 보상 1회를 반드시 지급한다.
- [ ] 상위 보상은 고급 이상 장비 또는 유물 후보다.
- [ ] 보물 노드는 유물 1개를 확정 지급한다.
- [ ] 보스 노드는 유물 1개 + 해금 체크 1회를 확정 지급한다.
- [ ] 보상 결과가 비어 있으면 버그로 처리한다.
## 13-5. 맵 / 이벤트 / 상점 / 모닥불
- [ ] 맵 노드는 일반 전투 / 이벤트 / 보물 / 상점 / 모닥불 / 유니크 몬스터 / 보스만 사용한다.
- [ ] 이벤트는 최소 2개 선택지를 가진다.
- [ ] 이벤트 실패는 HP / MP / 골드 감소, 상태이상, 전투 발생 중 하나로 귀결된다.
- [ ] 이벤트 처리는 끝난 뒤 반드시 다음 노드로 이어진다.
- [ ] 상점은 장비 / 유물 / 물약을 판매한다.
- [ ] 모닥불은 최대 HP의 35% 회복을 제공한다.
- [ ] 모닥불 투자로 스탯 1개를 +1 할 수 있고 비용은 25골드다.
- [ ] 장비 강화는 +3까지 허용한다.
- [ ] 장비 강화 비용은 등급별 비용 테이블로 관리한다.
## 13-6. 데이터 계약
- [ ] CharacterTable이 필요하다.
- [ ] SkillTable이 필요하다.
- [ ] EnemyTable이 필요하다.
- [ ] RelicTable이 필요하다.
- [ ] EquipmentTable이 필요하다.
- [ ] NodeTable이 필요하다.
- [ ] EventTable이 필요하다.
- [ ] RewardTable이 필요하다.
## 13-7. 1막 콘텐츠 최소 조건
- [ ] 1막 일반 적 / 엘리트 적 / 유니크 적은 분리된 풀로 관리한다.
- [ ] 1막 이벤트는 최소 4종을 구현한다.
- [ ] 1막 보스는 1종만 구현한다.
- [ ] 1막은 튜토리얼 성격의 붉은 달 아래 폐허 테마를 유지한다.
## 13-8. 검증 기준
- [ ] 전투 코어는 GUT 테스트로 검증한다.
- [ ] 상태이상은 GUT 테스트로 검증한다.
- [ ] 보상 루프는 GUT 테스트로 검증한다.
- [ ] 맵 노드 이동은 GUT 테스트로 검증한다.
- [ ] 1막 완주 수동 플레이 시나리오를 통과해야 한다.
## 14. 연출 / UI 최소 스펙
이 섹션은 MVP에서 최소한 보장해야 하는 화면 정보와 피드백 규칙이다. 구현 시 이 기준을 충족해야 한다.
## 14-1. 전투 HUD
- [ ] 모든 캐릭터와 적의 HP를 확인할 수 있어야 한다.
- [ ] 파티 캐릭터의 MP를 확인할 수 있어야 한다.
- [ ] 현재 턴 순서 또는 다음 행동 순서를 확인할 수 있어야 한다.
- [ ] 상태이상 아이콘과 남은 지속 턴 수를 확인할 수 있어야 한다.
- [ ] 행동 선택 시 대상과 비용이 즉시 드러나야 한다.
## 14-2. 맵 UI
- [ ] 현재 위치와 다음으로 갈 수 있는 노드를 구분해서 보여준다.
- [ ] 노드 타입은 전투 / 이벤트 / 보물 / 상점 / 모닥불 / 유니크 몬스터 / 보스로 구분되어 보여야 한다.
- [ ] 선택 가능한 경로만 강조하고, 선택 불가 경로는 비활성 표시한다.
## 14-3. 이벤트 UI
- [ ] 이벤트는 선택지 텍스트가 한눈에 읽히도록 배치한다.
- [ ] 선택 결과는 성공 / 실패 / 보상 / 상태이상 / 전투 발생이 즉시 이해되도록 표시한다.
- [ ] 이벤트 종료 후 다음 노드로 진행됨을 명확히 보여준다.
## 14-4. 연출 최소 규칙
- [ ] 공격 적중과 피격은 최소한의 이펙트 또는 흔들림으로 구분한다.
- [ ] 치명타는 일반 타격과 다른 피드백을 제공한다.
- [ ] 상태이상 부여 시 해당 상태의 아이콘 또는 텍스트 피드백을 보여준다.
- [ ] 승리 / 패배 / 보상 획득은 각각 별도 결과 연출을 가진다.
## 14-5. 사운드 최소 규칙
- [ ] 기본 공격과 스킬 사용은 서로 다른 피드백을 가진다.
- [ ] 피격 / 상태이상 / 보상 획득 / UI 선택에 최소한의 사운드 구분을 둔다.
## 14-6. 검증 기준
- [ ] 전투 중 필요한 정보가 모두 한 화면에서 확인 가능해야 한다.
- [ ] 맵에서 현재 선택 가능한 경로를 즉시 판별할 수 있어야 한다.
- [ ] 이벤트의 결과가 선택 직후 이해 가능해야 한다.
- [ ] 전투 / 보상 / 상태이상 / 승패가 피드백 없이 지나가지 않아야 한다.
## 15. 그래픽 최소 스펙
이 섹션은 MVP 그래픽 고정값이다. 아래 수치와 규칙은 구현 중 임의 변경하지 않는다. 변경이 필요하면 별도 스펙 수정으로 처리한다.
## 15-1. 화면 / 카메라
- [ ] 기본 화면 비율은 16:9, 타겟 해상도는 1920x1080으로 고정한다.
- [ ] 전투 / 맵 / 이벤트는 2D 고정 카메라를 사용한다. 전투에서만 피격 시 최대 ±6% 카메라 흔들림을 허용한다.
- [ ] HP / MP / 상태이상 / 행동 선택 UI는 화면 하단 20%와 상단 20% 밖으로 벗어나지 않는다.
## 15-2. 아트 스타일
- [ ] 1막 자산은 2D 일러스트풍 비픽셀 스타일로 통일한다. 외곽선 두께와 명암 단계는 동일한 기준을 공유한다.
- [ ] 아군은 청록 / 파랑, 적은 적색 / 주황, 상호작용은 금색, 경고는 노랑, 보조는 보라를 기본 색상 규칙으로 사용한다. 색만으로 구분하지 않고 실루엣 / 아이콘도 함께 사용한다.
- [ ] 모든 신규 자산은 외곽선 두께 2~4px, 광원 방향 우상단, 채도 중간 이상 규칙을 따른다.
## 15-3. 전투 가독성
- [ ] 행동 선택 시 대상 테두리를 1색으로 강조하고, 공격자 / 피격자는 밝기 또는 위치 변화로 즉시 구분한다.
- [ ] 피해 숫자는 0.2초 안에 나타나야 하고, HP 바 감소는 0.25초 이내에 완료되어야 한다. 상태이상은 아이콘과 남은 턴 숫자로 즉시 표시한다.
- [ ] 치명타는 금색 텍스트 + 120% 스케일 + 별도 사운드, 회복은 초록색, 방어는 파랑, 상태이상은 보라색 계열로 구분한다.
## 15-4. 노드 / 맵 가독성
- [ ] 노드 타입은 전투=붉은 검, 이벤트=보라 두루마리, 보물=금색 상자, 상점=초록 가방, 모닥불=주황 불꽃, 유니크=은색 왕관, 보스=검은 해골 아이콘으로 구분한다.
- [ ] 선택 가능 경로는 100% 불투명도로 표시하고, 선택 불가 경로는 35% 불투명도로 표시한다.
- [ ] 현재 위치는 흰색 펄스 링으로 표시하고 1.5초마다 한 번씩 강조된다.
## 15-5. UI 스타일
- [ ] 전투 HUD는 아군 하단 좌측, 적 상단, 행동 버튼 하단 중앙, 턴 순서 바 상단으로 배치한다. 숫자 표기는 본문 24px, 라벨 20px, 중요 수치 28px 이상으로 유지한다.
- [ ] 이벤트 UI는 설명 영역 1개, 선택지 영역 1개, 결과 토스트 1개로 분리한다. 선택지는 최소 2개, 결과는 성공 / 실패 / 보상 / 전투 중 하나를 즉시 읽을 수 있어야 한다.
- [ ] 폰트는 Pretendard 또는 Noto Sans KR 계열의 산세리프를 사용하고, 본문은 24px 이상, 경고 문구는 28px 이상으로 유지한다.
## 15-6. 애니메이션 / 이펙트 최소 기준
- [ ] 기본 공격 0.35초, 피격 플래시 0.12초, 상태이상 표시 0.15초, 보상 팝업 0.3초, 승리 / 패배 연출 0.5초 이내로 끝낸다.
- [ ] 기본 이펙트는 스킬당 12개 이하의 파티클만 사용한다. 화면 전체를 가리는 연출이나 과한 카메라 연출은 MVP에서 금지한다.
- [ ] 상태이상 부여와 해제는 아이콘 1개와 짧은 텍스트 1개로 표시하고, 남은 턴 수는 숫자 배지로 붙인다.
## 15-7. 검증 기준
- [ ] 플레이어는 전투 상태를 숫자만 보고도 읽을 수 있어야 한다. HP / MP / 상태이상 / 턴 순서가 한 화면에 보여야 한다.
- [ ] 맵에서 진행 가능 경로는 1초 안에 즉시 구분 가능해야 한다.
- [ ] 이벤트와 전투 결과는 텍스트 없이 봐도 승패 / 보상 / 상태이상 여부를 구분할 수 있어야 한다.
## 15-8. 캐릭터 / 적 / UI 레퍼런스 규칙
이 섹션은 MVP 그래픽을 실제로 그릴 때 해석이 갈리지 않도록 만드는 기준이다. 레퍼런스 없이 새로 판단하지 않는다.
## 15-8-1. 캐릭터 실루엣
- [ ] 플레이어 3인은 멀리서 봐도 역할이 구분되는 실루엣을 사용한다.
- [ ] 전위 딜러는 넓은 어깨와 공격적인 자세를 사용한다.
- [ ] 수호자는 방어형, 수직 비중심 실루엣을 사용한다.
- [ ] 마법 지원가는 장신 / 경량 실루엣과 장식이 많은 장비를 사용한다.
- [ ] 캐릭터당 기본 팔레트는 2~3개의 주색으로 제한한다.
## 15-8-2. 적 실루엣
- [ ] 일반 적은 역할이 즉시 읽히는 단순 실루엣을 사용한다.
- [ ] 엘리트는 일반 적보다 20% 이상 큰 덩치 또는 장식 요소를 가진다.
- [ ] 보스는 화면에서 가장 강하게 보이도록 높이 / 폭 / 장식량 중 최소 2개를 최상위로 둔다.
- [ ] 유니크 몬스터는 보스와 일반 적의 중간 위상으로 구분된다.
## 15-8-3. UI 레퍼런스
- [ ] 전투 HUD는 정보량이 많더라도 한눈에 읽히는 RPG HUD를 기준으로 한다.
- [ ] 맵 UI는 노드 그래프를 직관적으로 보여주는 심플한 라인 맵을 기준으로 한다.
- [ ] 이벤트 UI는 카드형 선택지 / 분기형 결과 표시를 기준으로 한다.
- [ ] 아이콘은 텍스트보다 먼저 인식되도록 굵고 단순한 형태를 사용한다.
## 15-8-4. 레퍼런스 금지 항목
- [ ] 실루엣만으로 역할이 구분되지 않는 캐릭터 디자인은 금지한다.
- [ ] 색만 다르고 형태가 같은 적 변형은 금지한다.
- [ ] UI 장식이 정보 가독성을 방해하는 구성은 금지한다.
## 15-8-5. 검증 기준
- [ ] 3명의 아군은 썸네일 크기에서도 서로 다른 역할로 보인다.
- [ ] 적 4종 이상은 실루엣만 보고도 등급이 구분된다.
- [ ] UI는 장식 없이도 정보 위치가 즉시 파악된다.
## 16. 데이터 계약 세부
이 섹션은 구현자가 테이블을 만들 때 필요한 최소 필드 정의다. 누락 필드는 구현 전에 새로 해석하지 않는다.
### 16-1. CharacterTable
- 필수 필드: character_id, name, role, max_hp, max_mp, attack, defense, speed, crit_rate, effect_accuracy, effect_resistance, skill_ids
- role 값: front / guardian / support 중 하나
### 16-2. SkillTable

### 16-3. EnemyTable

### 16-4. RelicTable

### 16-5. EquipmentTable

## 17. 1막 실제 콘텐츠 로스터 v0.1
이 섹션은 1막에 실제로 들어갈 콘텐츠의 초안 목록이다. 개수와 역할을 우선 고정하고, 명칭은 후속 수정 가능하다.
### 17-1. 일반 적 풀 (6)
- 녹슨 검병: 근접 단일 딜러. 방어 태세와 기본 참격을 사용한다.
- 붉은 사냥견: 속도가 빠르고 출혈을 건다. 후열 우선 타격 성향을 가진다.
- 그을린 궁수: 원거리 딜러. 화상을 건다.
- 파쇄 집사: 방어력 감소와 파쇄를 건다.
- 균열 병졸: 둔화 중심의 전열 적이다.
- 달빛 사제: 약화와 소규모 버프를 함께 쓰는 지원형 적이다.
### 17-2. 엘리트 풀 (3)
- 철갑 감시자: 방어 / 가드 중심. 장기전 유도형.
- 화염 집행관: 광역 화상과 압박형 공격을 사용한다.
- 붉은 달 의식사: 약화 / 파쇄 / 상태이상 혼합형. 패턴 전환이 있다.
### 17-3. 유니크 풀 (2)
- 봉인된 문지기: 반격형 유니크. 방어 강화 후 강한 단일 반격을 사용한다.
- 달의 사냥꾼: 고속 burst형 유니크. 행동 순서를 흔드는 패턴을 사용한다.
### 17-4. 보스 (1)
- 붉은 달의 파수꾼: 2페이즈 보스. 1페이즈는 참격 / 낙인 / 장막, 2페이즈는 광역 폭주 / 연속 타격 / 수호 해제로 전환한다.
### 17-5. 이벤트 (4)
- 무너진 제단: HP / MP를 일부 소모해 회복 또는 유물을 얻는 선택형 이벤트.
- 폐허 상인: 골드로 장비 / 물약 / 소형 강화 재료를 구매하는 상점형 이벤트.
- 봉인된 병실: 치료 / 해방 / 약탈 중 하나를 고르며, 실패 시 전투가 발생할 수 있다.
- 달빛 균열: 위험을 감수하면 유물 후보를 얻고, 실패하면 상태이상 또는 전투로 이어진다.
### 17-6. 유물 (6)
- 붉은 달의 파편: 첫 치명타 발생 시 추가 피해 또는 추가 턴 보정 중 하나를 주는 유물.
- 녹슨 방패편: 방어 행동 직후 방어 수치가 잠시 상승하는 유물.
- 사냥개의 이빨: 출혈 관련 수치가 강화되는 유물.
- 재의 잔향: 화상 부여와 화상 유지에 보정을 주는 유물.
- 균열의 실: 둔화 / 파쇄 관련 상태이상 성공률에 보정을 주는 유물.
- 고요한 종: 이벤트 페널티를 완화하거나 회복 효율을 높이는 유물.
### 17-7. 장비 (12)
- 무기: 녹슨 검 / 붉은 달 단도 / 균열 완드 — 공격력 또는 치명타 중심.
- 방어구: 견고한 흉갑 / 사냥견 가죽갑 / 의식가 로브 — HP 또는 방어 중심.
- 액세서리: 붉은 실 반지 / 달빛 부적 / 파편 목걸이 — 효과 적중 / 속도 / 저항 중심.
- 트링킷: 봉인된 열쇠 / 고요한 종 / 재의 조각 — 이벤트 보정 / 회복 보정 / 런 보정 중심.
- 장비 총수는 12개로 시작하며, 각 슬롯별 최소 3개씩 확보한다.
### 17-8. 1막 적 / 보상 / 패턴 연결 규칙
- 일반 적은 출혈 / 화상 / 둔화 / 파쇄 / 약화 중 하나를 중심으로 설계한다.
- 엘리트는 2개 이상의 상태이상 압박을 사용한다.
- 유니크는 일반 적과 엘리트 사이의 난이도 경계 역할을 한다.
- 보스는 2페이즈와 4개 이상의 고유 패턴을 가진다.
- 이벤트 / 유물 / 장비는 1막 테마와 기능이 직접 연결되도록 한다.

## 18. 최종 스펙 보강 v0.1
이 섹션이 13~15장과 17-9장의 해석 기준을 최종적으로 보강한다. 앞선 초안과 충돌하면 이 섹션을 우선 적용한다.
### 18-1. 구현 완료 판정
- 전투: 일반 / 엘리트 / 유니크 / 보스가 각각 1종 이상 구현되고, 상태이상 6종과 치명타 / 저항 / 보상 처리까지 동작해야 한다.
- 맵: 일반 전투 / 이벤트 / 보물 / 상점 / 모닥불 / 유니크 / 보스 노드가 모두 연결되고, 다음 노드 선택이 막히지 않아야 한다.
- 콘텐츠: 1막 로스터 수량은 일반 6 / 엘리트 3 / 유니크 2 / 보스 1 / 이벤트 4 / 유물 6 / 장비 12를 정확히 만족해야 한다.
- 데이터: CharacterTable / SkillTable / EnemyTable / RelicTable / EquipmentTable / NodeTable / EventTable / RewardTable의 필수 필드가 모두 채워져야 한다.
- 검증: GUT 테스트와 1막 수동 플레이스루에서 전투 승패, 보상, 이벤트 분기, 보스 클리어 판정이 재현 가능해야 한다.
### 18-2. 보스 패턴 최종 규칙
- 붉은 달의 파수꾼은 HP 50%를 페이즈 전환 기준으로 사용한다. 현재 행동을 끝낸 뒤 다음 턴 시작 시 2페이즈로 전환한다.
- 1페이즈 루프: 참격 → 장막 → 연속 참격 → 수호 준비 순서로 4턴 루프를 사용한다.
- 2페이즈 루프: 광역 폭주 → 연속 타격 → 낙인 / 수호 해제 → 재정렬 순서로 4턴 루프를 사용한다.
- 같은 종류의 광역 공격은 연속 2회 이상 사용하지 않는다. 페이즈 첫 턴에는 항상 준비 동작을 1회 넣는다.
### 18-3. 이벤트 분기 최종 규칙
- 모든 이벤트는 최소 2개 선택지를 가진다. 진행이 막히는 이벤트는 허용하지 않는다.
- 무너진 제단: 기도는 100% 유물 선택, 봉헌은 100% 보상, 파괴는 50% 전투 / 50% 유물 1개로 확정한다.
- 폐허 상인: 강탈은 60% 성공 / 40% 전투로 확정한다. 성공 시 골드 보너스, 실패 시 전투로 끝낸다.
- 봉인된 병실: 치료는 HP 회복, 해방은 디버프 해제 + 골드, 약탈은 50% 장비 / 50% 전투로 확정한다.
- 달빛 균열: 탐사는 65% 유물 후보 / 35% 전투, 봉인은 다음 전투의 적 속도 -2, 수용은 HP -10% + 장비 1개로 확정한다.
### 18-4. 유물 / 장비 효과 해석 규칙
- 추가 피해는 해당 발동 1회에만 적용되는 최종 피해 증가로 계산한다.
- 회복 효율은 모든 치유량에 곱연산으로 적용한다. 예: 회복 효율 +10%는 회복량 ×1.1이다.
- 이벤트 페널티 감소는 HP / MP / 골드 손실을 먼저 계산한 뒤, 감소율을 적용한다.
- 런 보정은 현재 런에서만 유지되며 메타 영구 성장으로 전이되지 않는다.
- 고유 효과 개방은 +3에서 추가 문구가 열리는 것을 뜻하며, 신규 시스템이 아니라 기존 효과의 확장이다.
### 18-5. 적 AI 우선순위
- 적 AI는 우선순위표 방식으로 동작한다. 조건이 맞는 가장 높은 우선순위의 행동 1개만 실행한다.
- 우선순위는 보통 threshold 반응 > 상태이상 부여 > 고계수 공격 > 기본 공격 순서로 둔다.
- 조건이 불충족이면 해당 행동은 건너뛰고 다음 후보를 평가한다. 모든 후보가 실패하면 기본 공격을 사용한다.
- 엘리트 / 유니크 / 보스는 ai_pattern_id에 정의된 고정 루프를 사용하고, 일반 적만 가벼운 가중치 랜덤을 허용한다.
- run_id, seed, node_index, node_type, result
- battle_type, enemy_name, turns, damage_dealt, damage_taken
- crit_count, status_success_rate, final_hp, final_mp
- gold_change, relic_count, equipment_count
- 일반 2~4턴, 엘리트 4~6턴, 보스 6~8턴을 핵심 판정 기준으로 본다

## 19. 미정 UI 스펙 보강 v0.1
이 섹션은 문서에서 명시되지 않은 UI의 기본 동작과 화면 공통 규칙을 정의한다. 앞선 UI 절과 충돌하면 이 섹션을 우선 적용한다.
### 19-1. 공통 레이아웃 / 레이어 규칙
- 모든 화면은 16:9 기준으로 제작하고, 실제 레이아웃 기준 해상도는 1920x1080으로 고정한다.
- 안전 여백은 화면 사방 48px로 두고, 중요한 정보와 버튼은 이 범위를 넘지 않는다.
- UI 레이어 순서는 배경 → 정보 패널 → 상호작용 요소 → 모달/토스트 순으로 고정한다.
- 모달이 열리면 배경 상호작용은 차단하고, 배경 dim은 60%로 통일한다.
### 19-2. 공통 버튼 / 카드 규격
- 기본 버튼 높이는 56px, 최소 터치 폭은 240px로 둔다.
- 버튼 상태는 기본 / hover / pressed / disabled 4종으로 통일한다.
- 주요 행동은 primary, 보조 행동은 secondary, 되돌리기나 위험 행동은 destructive 스타일을 사용한다.
- 카드는 제목 1줄, 본문 2줄, 보조 정보 1개 정도를 한눈에 읽히는 밀도로 유지한다.
### 19-3. 정보 표기 / 툴팁 규칙
- 숫자 정보는 단위와 증감 방향을 함께 표기한다. 예: +20, 35%, 2턴.
- 대상이 필요한 스킬/행동은 선택 전에도 효과 범위와 비용을 미리 보여준다.
- 추가 설명은 툴팁 또는 상세 패널로 제공하며, 텍스트는 2줄 안에서 핵심만 보여준다.
- 중복 경고는 한 번만 띄우고, 같은 경고가 반복되면 아이콘/배지 상태만 갱신한다.
### 19-4. 공통 피드백 / 토스트 규칙
- 짧은 알림은 상단 중앙 토스트로 표시하고, 지속 시간은 1.5초를 기본값으로 한다.
- 획득 / 손실 / 상태이상 / 실패는 각각 다른 색상과 아이콘을 사용한다.
- 중요 결과(보상, 승리, 패배, 해금)는 토스트만으로 끝내지 않고 별도 결과 패널을 띄운다.
- 이펙트가 없는 숫자 변화는 최소한의 사운드와 텍스트 강조로 보완한다.
### 19-5. 화면별 미정 UI 기본값
- 맵 화면은 노드 클릭 시 우측 또는 하단에 1칸짜리 노드 정보 패널을 띄워 노드 타입, 예상 보상, 위험도를 요약한다.
- 전투 화면은 턴 순서 바와 대상 정보 패널을 항상 노출하고, 스킬 선택 시 하단 중앙에 비용/대상/설명 미리보기를 보여준다.
- 이벤트 화면은 설명 영역과 선택지 영역을 분리하고, 선택지는 최소 2개 / 최대 4개까지 한 화면에 노출한다.
- 상점 화면은 아이템 카드에 가격, 보유 수량, 구매 가능 여부를 함께 표기한다.
- 모닥불 화면은 회복과 투자 두 선택지만 기본 제공하고, 각각의 결과 수치를 선택 전에도 보여준다.
- 보상 / 결과 화면은 획득 항목을 카드 단위로 나열하고, 닫기 전까지 다음 진행을 막는다.
### 19-6. 확인 / 취소 다이얼로그 규칙
- 골드 소비, 아이템 폐기, 노드 이탈, 전투 포기처럼 되돌리기 어려운 행동은 반드시 확인 다이얼로그를 요구한다.
- 확인 다이얼로그는 문장 1개 + 행동 버튼 2개(확인 / 취소)로 단순하게 구성한다.
- 위험 행동의 확인 버튼은 destructive 색상을 사용하고, 취소 버튼은 secondary 색상을 사용한다.
